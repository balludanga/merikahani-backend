Tests are organized as one Pytest module per feature area (`test_root.py`, `test_auth.py`, `test_posts.py`, `test_features.py`) sharing a single `conftest.py` at the package root. The shared `test_client` fixture wraps `fastapi.testclient.TestClient(app)` against `app.main.app` and uses `unittest.mock.patch` to stub Google's userinfo endpoint and the `GOOGLE_CLIENT_ID` setting so Google login can be exercised without external dependencies. Two pre-seeded writer fixtures (`writer_a`, `writer_b`) register unique users via `/api/auth/register` then log in once per test module (`scope="module"`) and return Bearer authorization headers for downstream post/feature tests. Dependency direction is strictly inward: test modules depend on `app.main` and `app.api.endpoints.auth`; nothing in `app/` imports from `tests/`.
