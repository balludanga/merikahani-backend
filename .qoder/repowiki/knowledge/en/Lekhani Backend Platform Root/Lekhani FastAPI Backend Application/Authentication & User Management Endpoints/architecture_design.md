Three files form a thin layer over shared infrastructure:
- `app/models/user.py` declares the `User` SQLAlchemy ORM class (table `users`) with relationships to `Post`, `Comment`, and `Follow` via `back_populates`/`foreign_keys`.
- `app/api/endpoints/auth.py` defines an `APIRouter` exposing `/google-login`, `/register`, `/login`, and `/me`. It delegates token signing/verification and password hashing to `app.core.security`, dependency injection (`get_db`, `get_current_user`) to `app.core.dependencies`, DB access to `app.database.get_db`, and request/response shapes to `app.schemas.user` (`Token`, `UserResponse`, `UserCreate`, `UserLogin`). Google login validates the id_token against `https://oauth2.googleapis.com/tokeninfo` using `settings.GOOGLE_CLIENT_ID` and auto-creates users on first sign-in.
- `app/api/endpoints/users.py` exposes `GET /{user_id}` returning a `UserProfileResponse` enriched with follower/following/post counts from the `Follow` and `Post` models; it uses `get_current_user_optional` so the endpoint works both authenticated and anonymous.
Dependency direction is one-way: endpoints → core.security/core.dependencies + schemas + models + database; there are no cross-imports between auth and users routers.
